Overview

MikeGPT answers LSU community questions by combining large language models with retrieval over institution-specific documents. The guiding principle: retrieval design matters more than model size. Investing in how context is found and grounded gives accurate, citable answers without relying on ever-larger models.

Architecture

Document processing

  • Ingests PDFs, web pages, policy documents, and academic resources, with OCR for scanned files.
  • Extracts metadata such as source, date, and department.
  • Chunks documents to preserve meaning while keeping retrieval precise.

Vector search

  • PostgreSQL with pgvector stores embeddings for semantic search beyond keyword matching.
  • Indexing is tuned to keep the 38,000+ document corpus fast to search.

Retrieval

  • Each agent picks the retrieval style that fits its task, such as FAQ keywording, syllabus filters, or navigational search.
  • The main Mike agent uses self-guided navigational search, from an AISX Lab paper, to gather the best context step by step before answering.
  • Retrieved context stays attached to each answer, so users can see what was used.

Response generation

  • Answers cite their source documents.
  • Retrieved context constrains generation to reduce hallucination.
  • Guardrails and automated checks run before a response is delivered.

My role

MikeGPT was built by a small team. I built one of its specialized agents end to end and contributed across the rest of the system.

Workday agent (built end to end)

  • Engineered its RAG pipeline, vector database schema, and semantic search. The architecture diagram above is this agent.
  • Built its Django and PostgreSQL backend services on Azure.

Across MikeGPT

  • Contributed, with the team, to the main RAG pipeline over 38,000+ documents, the custom agent engine for multi-step queries, and specialized agents for university domains.
  • Maintained and improved the application's backend, and made full-stack contributions.
